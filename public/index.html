Sign in

Your mind maps are saved as private JSON files in a repository called mindspark-maps on your own account. This app talks to your git host directly - there's no server in between.

Sign in with an access token
  1. Create the mindspark-maps repository →
    Set it to Private and tick Add a README. Already have it? Go to step 2.
  2. Create a fine-grained token →
    Repository access: Only select repositories → mindspark-maps.
    Permissions: Repository permissions → Contents → Read and write. Nothing else is needed.
    A token scoped this way can reach that one repository and nothing else in your account.
    Or use a classic token

    A classic token with the repo scope works too and creates the repository for you, so you can skip step 1. The trade-off: repo grants read/write to every private repository you own, so anything that got hold of the token would reach all of them.

The address you browse your repos at - just the origin, e.g. https://codeberg.org. Codeberg and gitea.com work as-is; a self-hosted instance also needs its origin added to this deployment's Content-Security-Policy, and MindSpark will tell you exactly what to add.
Where does the client ID come from?

Nobody can pre-register an OAuth app on your server, so you register one once: Settings → Applications → Create a new OAuth2 application on your instance.

Leave “Confidential Client” unchecked - MindSpark is a public client and uses PKCE, so there is no secret to store in your browser.

Your instance must also allow this page to make the token request: in app.ini, [cors] ENABLED = true. Codeberg has this on already. If it is off you'll get a clear message and can use an access token instead - that path needs no instance configuration.

Sign in with an access token
  1. Create an access token →
    Settings → Applications → Generate New Token. Select the write:repository scope (and read:user if your instance lists it). MindSpark creates the private mindspark-maps repo for you on first sign-in.
    Note: Gitea and Forgejo tokens are account-wide - they can't be scoped to a single repository the way GitHub's fine-grained tokens can, so this token reaches every repo on your account.
How does this work / is it safe?

MindSpark runs entirely in your browser. The token is stored only in localStorage on this device, and is sent only to the git host you signed in to - never to any third party. A Content-Security-Policy on this page blocks scripts and network calls to any other origin, so there is no route out for it. On GitHub, a fine-grained token also keeps the damage to one repository if that ever fails; Gitea and Forgejo have no per-repo token scoping, so their tokens are account-wide.

Because the token lives in this browser, treat signing in the way you would treat staying logged in anywhere: don't do it on a shared or untrusted machine, and sign out when you're done.

Every save commits a small JSON file to your mindspark-maps repo, so your data is versioned and you can git clone it any time. (On Gitea and Forgejo - and with a GitHub classic token - MindSpark creates that repo on first sign-in. A GitHub fine-grained token can't create repositories, which is why its step 1 exists.)

To revoke access on GitHub: fine-grained tokens / classic tokens. On Gitea or Forgejo: Settings → Applications on your instance.
